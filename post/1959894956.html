Section 8 Mutability

Python’s Data Model

Each object has:

  • An identity : never changes. Test with is
  • A Type : never changes
  • A value : can change for mutable objects. Cannot change for immutable objects. Test with ==

Variable reassignment vs. Object mutation

Reassigning a variable changes a blinding, it does not change(mutate) any object

Reassigning is always done via the syntax

Mutating (changing) an object does not change any variable blinding

New and old values

Every expression evaluates to value

  • It might be a new value
  • It might be a value that already exists

A constructor evaluates to a new value.

An access expression evaluates to an existing value.

Object identity

An object’s identity never changes

Can think of it as its address in memory.

Type

type(object) returns the type of an object.

Immutable objects

An immutable object can’t be changed after it is created.

Example : tuples are immutable. strings are also immutable

Although is immutable, we can use reassignment to make it “look like mutable”, despite copying a new

Mutable objects include list, dict, and set

Custom classes are generally mutable.

Mutable vs. Immutable

  • Immutable: quicker to access, expensive to change
  • Mutable : easy to change

Section 11 OOP

OOP can create your own data types and use them in programs.

To create a data type, we need to provide code that:

  1. instance variables
  2. constructors
  3. methods
  4. test client

Class vs. Objects

A class defines what an object should look like

An object is created based on that class

Class

  • class x : create class
  • __init__() method is automatically called when a new object is created
  • __str__() defines what is returned when an object is converted to a string. (When using print(obj))
  • The self parameter : a reference to the current instance of the class. It does not have to be named self, but it has to be the first parameter of any function in the class.
